# 🎨 GUI Generator Skill v1.4 — UNIFIED STANDARD

## 📋 ЗОЛОТЫЕ СТАНДАРТЫ (ВСЕГДА ВЫПОЛНЯЮТСЯ)

### 1. Стекло (Основное правило)
- **Материал:** `GRAY_STAINED_GLASS_PANE` (исключение: ничего)
- **Display name:** пусто (`' '`)
- **Расположение:** Header (слоты 1, 8), Row 1 (9-17 только в 54-слотовых), Footer (45-50, 52 опционально)

### 2. Слот 0 — ВСЕГДА уточнять
- **Профиль напрямую** (`head-%player_name%`): LoveAuth, LoveProfile, открыл лично о себе
- **Профиль косвенно** (`basehead-[Base64]`): LoveClans (голова клана), LoveHunt (охота), система/тема
- **Редкое исключение** (пусто/стекло): спросить обязательно
- **Правило:** Если сомневаешься — спроси перед генерацией

### 3. Header (Слоты 0-8)
- **Слот 0:** Голова (профиль или тема) — уточнить
- **Слот 1:** СТЕКЛО ВСЕГДА
- **Слоты 2-7:** Кнопки управления (вкладки, разделы, переключатели)
- **Слот 8:** СТЕКЛО ВСЕГДА
- **Правило:** Никаких исключений в header

### 4. Row 1 (Слоты 9-17) — КРИТИЧНОЕ ПРАВИЛО ⚠️
**Самая частая ошибка — спутать 27-слотовое с 54-слотовым**

- **27-слотовое меню:** Слоты 9-17 = **ПУСТО** (не используются никогда, не заполняй контентом)
- **54-слотовое меню:** Слоты 9-17 = **СТЕКЛО** (pure glass row, визуальный разделитель между header и рабочей зоной)
- **Причина:** В 27-слотовом слоты 9-17 — это вторая строка перед footer, она не должна быть видна или используется для контента. В 54-слотовом это разделитель перед большой рабочей зоной (18-44).

### 5. Рабочая зона (18-44, только 54-слотовое)
- **Слот 18:** ПУСТО или СТЕКЛО (левая стенка)
- **Слоты 19-25:** Контент (7 слотов) — кнопки/головы
- **Слот 26:** ПУСТО или СТЕКЛО (правая стенка)
- **Слот 27:** ПУСТО или СТЕКЛО (левая стенка)
- **Слоты 28-34:** Контент (7 слотов) — кнопки/головы
- **Слот 35:** ПУСТО или СТЕКЛО (правая стенка)
- **Слот 36:** ПУСТО или Пагинация ← (опционально, левая стенка)
- **Слоты 37-43:** Контент (7 слотов) — кнопки/головы
- **Слот 44:** ПУСТО или Пагинация → (опционально, правая стенка)

### 6. RULE 8: НЕТ СТЕКЛА В РАБОЧЕЙ ЗОНЕ (18-44) ⚡ КРИТИЧНОЕ

**Главное правило для красивого интерфейса:**

- **Запрещено:** Оставлять GRAY_STAINED_GLASS_PANE в рабочей зоне (слоты 18-44) там, где нет контента
- **Правильно:** Пустые слоты в центре рабочей зоны остаются **ПУСТО** (не заполняй стеклом)
- **Исключение:** Боковые стенки (слоты 18, 26, 27, 35, 36, 44) могут быть стеклом если нужна визуальная граница
- **Результат:** Интерфейс не разбивается визуально, контент "дышит", не создается "weird layout" эффект

**Пример НЕПРАВИЛЬНО (Rule 8 нарушена):**
```
Слот 19: базхед-кнопка
Слот 20: базхед-кнопка
Слот 21: СТЕКЛО ← ОШИБКА! Должно быть ПУСТО
Слот 22: СТЕКЛО ← ОШИБКА! Должно быть ПУСТО
```

**Пример ПРАВИЛЬНО (Rule 8 соблюдена):**
```
Слот 19: базхед-кнопка
Слот 20: базхед-кнопка
Слот 21: ПУСТО ✓
Слот 22: ПУСТО ✓
```

### 7. Footer (Слоты 45-53)
- **Слоты 45-50:** СТЕКЛО (6 слотов)
- **Слот 51:** Главное действие / Доп кнопка (например, "Создать заказ") ИЛИ СТЕКЛО
- **Слот 52:** Back (Назад) — перед кнопкой закрыть
- **Слот 53:** Close (Закрыть) — ВСЕГДА В ПОСЛЕДНЕМ СЛОТЕ (слот 53 в 54-слотовом меню)

### 8. ЗАПРЕЩЕННЫЕ КНОПКИ (СТРОГО ЗАПРЕЩЕНЫ В МЕНЮ) 🚫
- ❌ **Обновить меню** (Refresh) — меню обновляется автоматически при нажатиях/действиях.
- ❌ **Страница меню** (Page indicator paper/item) — предмет номера страницы в footer НЕ создается!
- ❌ **Сбросить фильтры** (Reset filters) — кнопка сброса фильтров не нужна.
- ❌ **Поиск по нику** (Search by nick) — кнопка поиска удалена из стандарта.

### 9. Пагинация (Слоты 36 и 44)
- **Условие:** Отображается **ТОЛЬКО если страниц больше 1** (`totalPages > 1` / много контрактов).
- **Слот 36:** Стрелка ← (предыдущая страница) — отображается только при наличи много контрактов.
- **Слот 44:** Стрелка → (следующая страница) — отображается только при наличии много контрактов.
- **Если 1 страница или пусто:** Слоты 36 и 44 остаются ПУСТЫМИ (стрелки не создаются).

### 10. Контент — ТОЛЬКО ГОЛОВЫ (Base64)
- **Функциональные кнопки, члены, предметы:** `basehead-[Base64]` или `%player_head%`
- **Стекло:** Только GRAY_STAINED_GLASS_PANE
- **Никогда:** Обычные материалы (DIRT, STONE, и т.д.) в функциональных кнопках
- **Если база64 нет:** Спроси значение перед генерацией

## 🎭 ИСКЛЮЧЕНИЯ ИЗ ПРАВИЛ

### Исключение 1: HOPPER МЕНЮ (Подтверждение/Отмена)

**Случай:** Меню подтверждения выбора (Yes/No, Confirm/Cancel, Delete/Keep)

**Архитектура (9 слотов, не 5):**
```
Слот:  0    1    2    3    4    5    6    7    8
      [S]  [✓]  [S]  [?]  [?]  [?]  [S]  [✗]  [S]

S = Стекло
✓ = Подтвердить
✗ = Отменить
? = Пусто (визуальный разделитель)
```

**Правила Hopper:**
- Слот 0: Стекло (или голова темы, если нужна идентификация)
- Слот 1: Подтверждение (✓) — `basehead-[Base64_yes]`
- Слоты 2-5: Пусто (визуальные разделители и пространство)
- Слот 6: Стекло (визуальный разделитель)
- Слот 7: Отмена (✗) — `basehead-[Base64_no]`
- Слот 8: Стекло

**YAML Пример:**
```yaml

size: 9

items:
  'glass_border':
    material: GRAY_STAINED_GLASS_PANE

    slots: [0,2,6,8]

  'btn_confirm':

    slot: 1
    display_name: '&aПодтвердить'
    left_click_commands:
```

**Когда:** Много контента (более 28 слотов), нужна навигация между страницами

**Расположение:**
- **Слот 36:** Стрелка ← (предыдущая страница) — `basehead-[Base64_arrow_left]`


### Исключение 3: ДОСТУПНАЯ КНОПКА (54-слотовое, слот 51)

**Когда:** Специальная функциональная кнопка кроме Back/Close (например, Reset, Settings, Help)

**Расположение:** Слот 51 (до Back и Close в footer)

**YAML Пример:**
```yaml

  material: basehead-eyJ0ZXh0dXJlcyI6eyJTS0lOIjp7InVybCI6Imh0dHA6Ly90ZXh0dXJlcy5taW5lY3JhZnQubmV0L3RleHR1cmUvOGVlN2I0YTMyMDJi...

  lore:
    - ''
    - '&7Вернуть стандартное отображение.'
    - '&aЛКМ &7— сбросить'
  left_click_commands:
    - '[console] lovesubnames reset %player_name%'
    - '[message] &7Пометки сброшены.'
```

### Исключение 4: НЕСТАНДАРТНЫЕ МЕНЮ (не 9, 18, 27, 54 слотов)

**Действие: СПРОСИТЬ перед генерацией про:**
1. Размер меню (почему не стандартный?)
2. Назначение и контент
3. Слот 0 (голова? тема? пусто?)
4. Расположение кнопок (есть ли боковые стенки?)

## 🎨 ВИД ОФОРМЛЕНИЯ (СТАНДАРТ)

### Цвета MiniMessage
```
&6 = gold      — основные кнопки, навигация
&a = green     — активные состояния, подтверждение
&c = red       — опасные действия, закрыть, отменить
&7 = gray      — описание, неактивный текст
&9 = blue      — офицеры, VIP, специальные роли
&f = white     — значения, информация, ключевые данные
&e = yellow    — внимание, уведомления, выделение
```

### Структура Lore (стандартная)
```
1. Пустая строка:           ''
2. Описание кнопки:         '&7Текст описания'
3. Значение (если есть):    '&7Значение: &fДанные'
4. Действие:                '&aЛКМ &7— открыть'
5. Доп действие (если есть):'&aПКМ &7— удалить'
```
